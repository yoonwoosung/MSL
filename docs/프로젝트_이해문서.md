## 1. 이 프로젝트가 뭔가? (30초 버전)

네트워크 트래픽 데이터를 보고 **"이게 정상인가, DDoS 공격인가"를 머신러닝으로 분류**하는 프로젝트다.

처음에 결과가 **정확도 100%** 나왔는데, 이게 진짜 잘 된 게 아니라 **데이터에 치팅이 있었던 것**이었다. 그 치팅(데이터 누수)을 찾아서 제거했더니 **99.79%**가 나왔고, 이게 진짜 성능이다.

> **핵심만 기억해**
> "100%는 자랑이 아니라 문제가 있다는 신호였다. 고친 뒤 99.79%가 진짜 결과다."

## 2. DDoS가 뭔가?

**Distributed Denial of Service** — 수많은 컴퓨터가 한 서버에 동시에 접속 요청을 퍼부어 서버를 다운시키는 공격.

- 예: 게임 서버, 인터넷 쇼핑몰, 은행 앱이 몇 시간 동안 안 켜지는 상황.
- 실제 피해: 수십억 원 손실 + 브랜드 신뢰도 추락.

**왜 머신러닝으로 탐지하나?**

기존 방법(규칙 기반): "이런 IP에서 오는 트래픽은 막아라" 처럼 미리 정해진 규칙으로 차단.
- 문제: 공격자가 IP를 바꾸거나 패턴을 조금만 바꾸면 뚫린다.

머신러닝 방법: 트래픽의 **행동 패턴**(패킷이 얼마나 크냐, 얼마나 빨리 오냐 등)을 학습해서 분류.
- 장점: 공격자 IP가 바뀌어도 행동 패턴이 비슷하면 탐지 가능.

> **핵심만 기억해**
> "주소(IP)를 보는 게 아니라 행동 패턴을 보기 때문에 새로운 공격에도 대응 가능하다."

## 3. 데이터가 어떻게 생겼나?

**Kaggle에서 받은 DDoS 트래픽 데이터셋** (`data/ddos_dataset.csv`)

| 항목 | 내용 |
|------|------|
| 크기 | 852,585행 (한 행 = 네트워크 트래픽 1건) |
| 컬럼 수 | 9개 |
| 정상 트래픽 | 454,849건 |
| 공격 트래픽 | 397,736건 |
| 비율 | 약 53:47 → **거의 균형** |

### 컬럼 설명

데이터에는 두 종류의 컬럼이 있다.

**① 식별자 컬럼** — "누가 보냈냐"를 나타냄 → **학습에서 반드시 제거해야 함**

| 컬럼명 | 의미 |
|--------|------|
| Source IP | 트래픽을 보낸 컴퓨터의 주소 |
| Destination IP | 트래픽을 받은 서버의 주소 |
| Source Port | 출발 포트 번호 |
| Destination Port | 도착 포트 번호 |

**② 행동 특성 컬럼** — "어떻게 보냈냐"를 나타냄 → **이것만 학습에 사용**

| 컬럼명 | 의미 |
|--------|------|
| Packet Length | 패킷 하나의 크기 (DDoS는 패턴이 다름) |
| Packets/Time | 단위 시간당 패킷 수 (DDoS는 폭발적으로 많음) |
| Highest Layer | 어떤 프로토콜을 사용했는지 |
| Transport Layer | 전송 계층 프로토콜 종류 |

> **핵심만 기억해**
> "IP·포트는 '누가'이고 Packet Length·속도는 '어떻게'. 우리는 '어떻게'만 보고 판단한다."

## 4. 핵심 스토리: 데이터 누수 (Data Leakage)

### 4-1. 데이터 누수가 뭔가?

**비유로 이해하기**

> 학교에서 중간고사를 본다고 하자.
> 선생님이 실수로 **시험 문제지를 공부 자료에 포함**시켰다.
> 학생은 100점을 맞았다. 근데 이게 진짜 실력인가?
> → 아니다. 문제를 미리 봤기 때문이다. 다른 문제가 나오면 못 풀 수 있다.

머신러닝에서 "데이터 누수"가 딱 이 상황이다.
- 모델이 **실전에서 절대 알 수 없는 정보(정답 단서)를 학습할 때 미리 본** 것.
- 결과: 학습/테스트에서는 완벽하지만, 실제 새 상황에서는 무너진다.

### 4-2. 이 프로젝트에서 누수가 어떻게 발생했나?

**문제의 시작**: IP 주소가 숫자로 저장되어 있었다.

```
Source IP: 192.168.1.1  →  실제 저장된 값: 3232235777 (숫자!)
```

**초기 코드**: "숫자 컬럼은 다 학습에 써라"

```python
# 이 코드가 문제였다
feature_df = df.select_dtypes(include=[np.number])
# → 숫자처럼 생긴 IP/Port가 전부 포함되어 버림
```

**왜 이게 문제인가?**

DDoS 데이터의 특성: **한 공격자 IP가 수천 개의 row를 만든다**.

```
공격자 IP: 3232235777  →  train 데이터에 3000번 등장, test 데이터에도 등장
```

그러면 모델이 학습하는 것이:
- "패킷이 얼마나 크고 빠른가?" (행동) ❌
- "이 IP 번호가 학습 때 공격자였나?" (주소 암기) ✅

결과: **train/test 모두 100% 정확도** — 왜냐면 test에도 같은 IP가 있으니까.
그리고 **feature importance 1위: Source IP (0.44)** — 모델 스스로 "IP가 가장 중요했다"고 말하는 것.

### 4-3. 어떻게 고쳤나?

**수정 1 — 식별자를 이름으로 직접 찾아서 제거**

숫자라도 이름이 IP·Port이면 무조건 지운다.

```python
ID_COLUMNS = [
    "source ip", "destination ip",
    "source port", "destination port",
    "flow id", "timestamp", ...
]
# 이 컬럼들은 무조건 학습 데이터에서 삭제
```

**수정 2 — 문자로 된 컬럼(Highest Layer 등)을 숫자로 변환**

머신러닝 모델은 숫자만 이해한다.
`Highest Layer: "TCP"` → `0`, `"UDP"` → `1` 이런 식으로 변환 (LabelEncoder).

**수정 3 — 정규화(StandardScaler)도 치팅 없이**

정규화: 서로 다른 스케일의 숫자들을 같은 기준으로 맞추는 작업.
- 패킷 크기(수천 단위)와 비율(0~1 단위)이 섞여 있을 때 정규화 필요.

**누수 없는 방법:**
```
train 데이터 통계(평균, 표준편차)로 정규화 기준을 정하고
test 데이터는 그 기준으로만 변환 (test 통계는 절대 사용 안 함)
```

**비유**: 채점 기준을 연습문제 풀이 결과로만 정하고, 실전 시험에는 그 기준을 그대로 적용.
만약 실전 시험 답안지를 먼저 보고 기준을 정하면 → 치팅.

### 4-4. 수정 전후 비교

| 항목 | 수정 전 | 수정 후 |
|------|:-------:|:-------:|
| Test Accuracy | **100%** (가짜) | **99.79%** (진짜) |
| 중요도 1위 특성 | Source IP (0.44) → 주소 암기 | Packet Length → 행동 학습 |
| 의미 | 공격자 IP를 외운 것 | 트래픽 패턴을 배운 것 |

> **핵심만 기억해**
> "100%는 IP를 외운 것. 99.79%는 행동을 배운 것. 후자가 진짜다."

## 5. 전처리 과정 전체 흐름

"전처리"란 데이터를 모델이 학습할 수 있게 깔끔하게 정리하는 과정.

```
① CSV 파일 불러오기 (852,585행)
        ↓
② 식별자 컬럼 삭제 (Source/Dest IP·Port 등 4개 제거)
        ↓
③ 문자 컬럼 → 숫자 변환 (Highest Layer, Transport Layer)
        ↓
④ 숫자 컬럼만 남기기
        ↓
⑤ 이상값(무한대) 및 빈 값 제거
        ↓
⑥ 정답 레이블 변환 (정상/공격 문자 → 0/1 숫자)
        ↓
⑦ 학습용(80%) / 테스트용(20%) 분할 → 클래스 비율 유지
        ↓
⑧ 정규화: 학습용 통계로만 기준 설정, 테스트는 그 기준 적용
        ↓
결과: 학습 682,068행 × 4특성 / 테스트 170,517행 × 4특성
```

> **핵심만 기억해**
> "9개 컬럼 → 식별자 4개 제거 → 행동 특성 4개만 학습에 사용"

## 6. 모델이란 뭔가? 왜 3개를 비교했나?

**모델**: 데이터의 패턴을 학습해서 새 입력에 대한 답을 내놓는 프로그램.
이 프로젝트에서 모델의 역할: 트래픽 4개 특성을 보고 "정상(0) or 공격(1)" 판단.

**왜 3개를 비교하나?**: "이 모델이 최선인가?"를 알려면 다른 모델과 비교해야 한다.
비교 조건: 동일한 데이터, 동일한 seed(42) → 공정한 비교.

### 6-1. 3개 모델 설명 (쉽게)

**① LogisticRegression (로지스틱 회귀)**
- 비유: 직선 하나를 그어서 두 그룹을 나누는 방식.
- 장점: 빠르고 해석이 쉬움. 기준선(베이스라인) 역할.
- 단점: 복잡한 패턴(구불구불한 경계)은 못 잡음.
- 학습 원리: "로그 손실(예측 틀린 정도)"을 줄여나가는 방식으로 학습.

**② DecisionTree (결정 트리)**
- 비유: 스무고개처럼 질문을 연속으로 해서 분류.
  - "패킷 크기 > 500?" → Yes → "속도 > 100?" → Yes → 공격
- 장점: 복잡한 경계도 그릴 수 있음.
- 단점: 학습 데이터에 너무 딱 맞게 학습되어 새 데이터에서 틀리는 경향(과적합).

**③ RandomForest (랜덤 포레스트)** ← 최종 선택
- 비유: 전문가 100명에게 물어보고 다수결로 결정.
  - DecisionTree 하나가 한 명의 전문가. RandomForest는 100명의 전문가 패널.
- 장점: 다수결이라 한 명이 틀려도 전체가 안 틀림 → 안정적.
- 특별한 장점: **feature_importances_** — "어떤 특성이 결정에 얼마나 기여했나" 수치로 보여줌.
  → 이걸로 누수 검증 가능 ("Source IP가 1등이면 아직 누수가 있는 것")

### 6-2. 비교 결과

| 모델 | 학습 정확도 | 테스트 정확도 | Gap(차이) | F1 |
|------|:-----------:|:------------:|:---------:|:--:|
| LogisticRegression | 98.95% | 98.95% | 0.00% | 0.9895 |
| DecisionTree | 99.84% | 99.80% | 0.04% | 0.9980 |
| **RandomForest** | **99.84%** | **99.79%** | **0.06%** | **0.9979** |

**Gap(과적합 차이)** 이란?
- 학습 정확도 - 테스트 정확도 = 얼마나 "암기"했냐의 지표.
- Gap이 클수록 학습 데이터를 외운 것 → 새 데이터에서 성능이 떨어질 수 있음.
- 세 모델 모두 Gap이 매우 작음 → 외운 게 아니라 배운 것.

### 6-3. 왜 RandomForest를 최종 선택했나?

1. **복잡한 패턴 처리**: 트래픽 데이터는 선형으로 딱 나뉘지 않음 → 트리 기반이 유리.
2. **안정성**: 100개 트리 다수결 → DecisionTree 하나보다 훨씬 안정적.
3. **설명 가능**: feature importance로 "왜 이렇게 판단했나" 보여줄 수 있음.
4. **스케일 무관**: 패킷 크기(수천)와 비율(0~1)이 섞여 있어도 잘 동작.

> **핵심만 기억해**
> "전문가 100명 다수결(RF)이 한 명(DT)보다 안정적이고, 판단 근거도 설명 가능하다."

## 7. 하이퍼파라미터 튜닝

### 7-1. 하이퍼파라미터가 뭔가?

**비유**: 요리 레시피에서 불 세기, 시간, 재료 비율처럼 **조리 전에 사람이 미리 정하는 설정값**.
모델이 학습하면서 스스로 배우는 것(가중치)과 다르게, 튜닝은 사람이 실험으로 찾는 것.

| 파라미터 | 의미 | 영향 |
|---------|------|------|
| `n_estimators` | 트리 몇 개 쓸 건지 | 많을수록 안정적이지만 느림 |
| `max_depth` | 트리 깊이 제한 | 너무 깊으면 과적합 |
| `min_samples_split` | 가지를 나누려면 최소 몇 개 샘플 필요 | 클수록 단순한 트리 |
| `min_samples_leaf` | 잎 노드에 최소 몇 개 샘플 필요 | 과적합 방지 |
| `max_features` | 각 분할 시 고려할 특성 수 | 다양성 확보 |

### 7-2. GridSearchCV란?

**비유**: 모든 조합의 레시피를 다 만들어보고 가장 맛있는 걸 찾는 것.

- 우리가 정의한 조합: **48가지** (2×3×2×2×2)
- 각 조합마다 **3번 교차검증** = 총 **144번 학습**

**교차검증(cross-validation)**: 학습 데이터를 3개로 나눠서 돌아가며 검증.

```
[fold1: 검증] [fold2: 학습] [fold3: 학습] → 1번 결과
[fold1: 학습] [fold2: 검증] [fold3: 학습] → 2번 결과
[fold1: 학습] [fold2: 학습] [fold3: 검증] → 3번 결과
→ 3번 평균 = 이 조합의 실력
```

이렇게 하면 테스트 데이터를 건드리지 않고도 어떤 설정이 더 나은지 비교 가능.

### 7-3. 튜닝 결과

- **정규 튜닝 (48조합)**: 최적 F1 0.9981 vs 기본값 F1 0.9979 → **차이 0.0002**
- **극단적 튜닝 (80조합)**: 최적 F1 0.9980 vs 기본값 F1 0.9979 → **차이 0.0001**
- **최악 조합** (`max_depth=2`, 트리를 너무 단순하게): F1 0.9632

### 7-4. 왜 튜닝 효과가 이렇게 작나? (중요한 고찰)

이 부분은 "왜 튜닝을 안 했냐"는 질문에 대비해 꼭 이해해야 한다.

**이유 1 — sqrt와 log2가 수치상 같다**
특성이 4개이면: `√4 = 2`, `log₂4 = 2` → 두 옵션이 결과적으로 같은 수.
→ `max_features` 파라미터가 사실상 효과가 없음.

**이유 2 — 데이터가 68만 행으로 매우 많다**
데이터가 많으면 모델은 어떤 설정이든 충분히 수렴(안정적인 결과에 도달)한다.
한 두 개 설정을 바꿔봐도 거대한 데이터 앞에서 큰 차이가 안 난다.

**이유 3 — RF 배깅 구조 자체가 파라미터 차이를 흡수**
100개 트리가 서로 다른 부분을 커버하기 때문에, 개별 트리 설정이 조금 달라도 전체 결과는 비슷하게 수렴.

> **핵심만 기억해**
> "튜닝을 안 한 게 아니라 128가지 조합을 실험했는데도 차이가 0.0001이었다.
> 즉, 기본값이 이미 이 데이터에서 최적이라는 걸 실험으로 검증한 것이다."

## 8. 성능 평가

### 8-1. 왜 정확도(Accuracy) 하나만 보면 안 되나?

**비유**: 암 진단 모델을 만들었다.
- 전체 환자 중 90%가 정상 → 모델이 "무조건 정상"이라고 해도 정확도 90%.
- 하지만 암 환자 10%를 전부 놓쳤다. 이게 좋은 모델인가? → 아니다.

보안에서도 마찬가지:
- **공격을 정상으로 오인** (FN, False Negative): 치명적 — 공격이 그냥 통과됨.
- **정상을 공격으로 오인** (FP, False Positive): 불편함 — 정상 사용자 차단.

두 종류의 실수 비용이 다르기 때문에, 여러 지표를 함께 봐야 한다.

### 8-2. 지표 설명

| 지표 | 의미 | 쉬운 설명 |
|------|------|----------|
| **Accuracy** | 전체 중 맞춘 비율 | 총 100번 중 99.79번 맞춤 |
| **Precision** | 공격이라고 한 것 중 진짜 공격 비율 | 공격이라고 경보 울렸을 때 실제 공격일 확률 |
| **Recall** | 진짜 공격 중 잡아낸 비율 | 실제 공격 중 몇 %를 탐지했나 |
| **F1-score** | Precision과 Recall의 균형 지표 | 둘 다 높아야 높은 점수 |
| **Overfit gap** | 학습 정확도 - 테스트 정확도 | 작을수록 "배운 것" 큰수록 "외운 것" |

### 8-3. 최종 성능

```
학습 정확도  : 99.84%
테스트 정확도 : 99.79%
Overfit gap  : 0.05%   ← 거의 없음 = 일반화 잘 됨

Precision    : 99.79%
Recall       : 99.79%
F1-score     : 99.79%
```

- **공격(1) Recall ≈ 99.65%**: 실제 공격 100건 중 99.65건 탐지.
- **Overfit gap 0.05%**: 학습 데이터를 외운 게 아니라 진짜 패턴을 배운 것.

### [기초 개념]

**Q. 머신러닝이 뭔가요?**
> 사람이 규칙을 직접 짜는 대신, 컴퓨터가 데이터에서 스스로 패턴을 찾아서 판단하는 기술입니다. 이 프로젝트에서는 수십만 건의 트래픽 데이터를 보여주면서 "이게 공격, 이게 정상"을 알려주면, 모델이 패턴을 학습해서 새 트래픽이 들어왔을 때 스스로 판단합니다.

**Q. 지도학습이 뭔가요?**
> 정답이 있는 데이터로 학습하는 방식입니다. 이 프로젝트에서는 각 트래픽마다 "이건 공격(1), 이건 정상(0)"이라는 정답 레이블이 있고, 그걸 보면서 학습합니다. 학생이 문제와 답을 함께 보면서 공부하는 것과 같습니다.

**Q. train/test 분리가 뭔가요?**
> 데이터를 학습용(80%)과 평가용(20%)으로 나눕니다. 학습할 때는 학습용 데이터만 보고, 성능을 평가할 때는 처음 보는 평가용 데이터로 테스트합니다. 시험공부할 때 연습문제로 공부하고, 실제 시험은 다른 문제로 보는 것과 같습니다. 같은 문제로 공부하고 같은 문제로 시험 보면 성적이 의미 없죠.

### [데이터 누수 관련]

**Q. 데이터 누수가 정확히 뭔가요?**
> 실전에서는 절대 알 수 없는 정보가 학습에 사용된 상태입니다. 이 프로젝트에서는 공격자 IP 주소가 학습 데이터와 테스트 데이터에 모두 등장해서, 모델이 "트래픽이 어떻게 생겼나"가 아니라 "이 IP가 공격자 목록에 있나"를 외워버렸습니다. 시험 문제지를 미리 보고 답을 외운 것과 같습니다.

**Q. IP가 숫자로 저장된 게 왜 문제인가요?**
> 원래 코드가 "숫자 컬럼은 다 학습에 사용"하도록 되어 있었는데, IP 주소가 `3232235777` 같은 숫자로 저장돼 있어서 그냥 통과해버렸습니다. 이름이 "Source IP"라는 걸 모르는 코드는 그냥 숫자 컬럼으로 인식해버린 거죠. 그래서 이름을 기준으로 명시적으로 삭제해야 했습니다.

**Q. 100%가 왜 문제인가요? 좋은 거 아닌가요?**
> 실제로 100%가 나올 수 있는 상황이 두 가지입니다. ① 정말 완벽한 모델 — 거의 불가능합니다. ② 치팅(데이터 누수) — 모델이 정답을 미리 본 것입니다. 이 프로젝트에서 feature importance를 보니 Source IP가 1위였습니다. 모델이 IP를 외웠다는 증거입니다. 실전에서 새로운 공격자(새 IP)가 나타나면 바로 무너집니다.

**Q. 스케일러도 누수가 생기나요?**
> 네. StandardScaler는 데이터의 평균과 표준편차를 계산해서 정규화합니다. 테스트 데이터까지 포함해서 계산하면, 테스트 데이터의 통계 정보가 학습 과정에 들어가는 것입니다. 실전에서는 미래 데이터의 통계를 미리 알 수 없습니다. 그래서 반드시 학습 데이터 통계로만 기준을 만들고, 테스트에는 그 기준만 적용합니다.

---

### [모델 관련]

**Q. 왜 RandomForest를 선택했나요?**
> 세 가지 이유입니다. ① 네트워크 트래픽 데이터는 선형으로 딱 나뉘지 않는 복잡한 패턴이 많아, 결정트리 앙상블(RF)이 유리합니다. ② 100개 트리의 다수결이라 한 두 개 트리가 틀려도 전체는 안 틀리는 안정성이 있습니다. ③ feature_importances_로 "어떤 특성이 판단에 기여했는지" 보여줄 수 있어 누수 검증에도 활용했습니다.

**Q. DecisionTree와 RandomForest의 차이는?**
> DecisionTree는 전문가 한 명이 결정하는 것이고, RandomForest는 전문가 100명이 각자 독립적으로 판단하고 다수결로 결정하는 것입니다. 전문가 한 명은 자신의 경험(학습 데이터)을 과도하게 따를 수 있지만(과적합), 100명이 다수결하면 그런 편향이 서로 상쇄됩니다.

**Q. LogisticRegression의 overfit gap이 왜 0인가요?**
> 로지스틱 회귀는 "직선 하나로 나누는" 단순한 모델이라, 학습 데이터의 세세한 노이즈를 외우는 능력이 없습니다. 그래서 학습 성능과 테스트 성능이 거의 같습니다. 과적합이 없는 건 장점이지만, 복잡한 패턴을 못 잡아서 F1이 약간 낮게 나옵니다.

**Q. 이 모델이 DDoS를 실제로 탐지하는 건가요?**
> 이 프로젝트는 이미 수집된 데이터로 "학습하고 검증하는 파이프라인"입니다. 데이터는 이미 정상/공격 레이블이 붙어 있고, 모델이 새 데이터에 대해 얼마나 잘 맞추는지 검증한 것입니다. 실제 실시간 네트워크에 연결해서 탐지하려면 추가 엔지니어링이 필요합니다. 이 프로젝트는 "탐지 가능성과 성능"을 검증한 단계입니다.

### [튜닝 관련]

**Q. 튜닝을 했는데 왜 성능이 거의 안 올랐나요?**
> 세 가지 이유입니다. ① 특성이 4개뿐이라 `sqrt(4) = log2(4) = 2`로 max_features 두 옵션이 수치상 같습니다. ② 데이터가 68만 행으로 매우 많아 어떤 설정이든 수렴합니다. ③ 랜덤포레스트의 배깅 구조가 개별 설정 차이를 흡수합니다. 실패가 아니라 기본값이 이미 최적이라는 걸 실험으로 증명한 것입니다.

**Q. 교차검증(CV)이 뭔가요?**
> 학습 데이터를 3개 그룹으로 나눠서 돌아가며 검증합니다. 첫 번째 실험: 그룹 1,2로 학습 → 그룹 3으로 검증. 두 번째: 그룹 1,3으로 학습 → 그룹 2로 검증. 세 번째: 그룹 2,3으로 학습 → 그룹 1로 검증. 이렇게 3번 평균을 내면 테스트 데이터를 건드리지 않고도 어떤 설정이 더 좋은지 공정하게 비교할 수 있습니다.

**Q. 극단적 탐색은 왜 했나요?**
> 정규 튜닝(48조합)에서 효과가 없자 "탐색 범위가 좁아서 그런 건가?"라는 의심이 생겼습니다. 그래서 트리 깊이를 2처럼 극단적으로 얕게, 트리 수를 10처럼 극단적으로 적게 설정하는 등 80가지 조합을 더 실험했습니다. 결과가 여전히 차이 0.0001이었으므로 "탐색이 부족해서가 아니라 기본값이 최적"이라는 결론을 내릴 수 있었습니다.

---

### [평가 지표 관련]

**Q. Precision과 Recall이 뭔가요?**
> **Precision**: 모델이 "공격"이라고 외친 것 중 실제로 공격인 비율. "경보 정확도"
> **Recall**: 실제 공격 중에서 모델이 잡아낸 비율. "공격 탐지율"
> 보안에서는 Recall이 더 중요합니다. 경보가 가끔 오발령 나는 건 괜찮지만(Precision 조금 낮아도), 실제 공격을 놓치면(Recall 낮으면) 치명적입니다.

**Q. F1-score가 뭔가요?**
> Precision과 Recall의 조화 평균입니다. 둘 중 하나만 높은 건 의미 없고 둘 다 높아야 높게 나옵니다. 예를 들어 모든 걸 "공격"이라고 하면 Recall은 100%지만 Precision은 낮아 F1도 낮아집니다.

**Q. feature importance가 뭔가요?**
> RandomForest 모델이 판단할 때 "어떤 특성에 얼마나 의존했나"를 수치로 보여주는 것입니다. 누수 제거 전에는 Source IP가 1위(0.44) — 모델이 IP를 보고 판단했다는 증거. 누수 제거 후에는 Packet Length가 1위 — 트래픽 행동을 보고 판단했다는 증거. 이 변화가 "누수를 제거했고 모델이 제대로 학습했다"는 가장 직관적인 증거입니다.

---

### [재현성 관련]

**Q. random_state=42가 뭔가요?**
> 머신러닝은 데이터를 나누거나 모델을 초기화할 때 랜덤 숫자를 씁니다. random_state를 42로 고정하면 항상 같은 랜덤 숫자를 씁니다. 즉 코드를 다시 돌려도 같은 결과가 나옵니다. 교수님이 채점하실 때도, 팀원이 다시 돌려봐도 동일한 결과가 나와야 신뢰할 수 있습니다.

**Q. stratify=y가 뭔가요?**
> train/test를 나눌 때 "정상:공격 비율을 원본과 동일하게 유지"하는 옵션입니다. 데이터가 53:47인데 우연히 test에 공격이 70% 몰리면 평가가 왜곡됩니다. stratify를 쓰면 train도 53:47, test도 53:47로 나뉩니다.

**Q. 이 모델의 한계는 무엇인가요?**
> 세 가지입니다. ① 하나의 데이터셋으로만 검증했습니다. 다른 네트워크 환경에서도 잘 동작하는지는 미확인입니다. ② 실시간 탐지 시스템으로 연결하려면 추가 개발이 필요합니다. ③ 공격 유형이 크게 변형되면 재학습이 필요합니다.

## 11. 발표 핵심 메시지 (반드시 외울 것)

> **"100%는 자랑이 아니라 문제의 증거였다."**
> → IP를 외운 게 100%, 행동을 배운 게 99.79%다.

> **"우리의 모든 선택에는 이유가 있다."**
> → 왜 이 모델인지, 왜 이 지표인지, 왜 train/test를 같이 보는지 다 설명 가능하다.

> **"튜닝 효과가 없는 게 결론이 아니다. 128가지 실험으로 기본값이 최적임을 검증한 것이 결론이다."**
