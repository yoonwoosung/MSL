# DDoS 탐지 머신러닝 프로젝트 — 발표 대본 (PPT 초안)

> 핵심 서사: **전공 문제 정의 → 누수 없는 전처리 → 이유 있는 모델 비교 → 튜닝으로 과적합 통제 → 맞는 지표로 평가 → 시드로 재현**
>
> 관통 메시지: **"100%는 자랑이 아니라 누수(leakage)의 증거였다. 식별자를 지운 뒤의 95~99%가 진짜 일반화 성능이다."**

## 슬라이드 4 — 전처리 & 데이터 누수 방지 ★핵심★

**(1) 넣을 내용**
- **누수의 정체**: 첫 버전은 `select_dtypes(np.number)`로 '숫자 컬럼 전부'를 학습에 사용 → IP·Port가 숫자로 저장돼 그대로 feature로 들어감.
- DDoS 데이터는 한 공격 IP가 수천 row 생성 → 같은 IP가 train/test 양쪽에 등장 → 모델이 '행동'이 아니라 '공격자 명단(IP)'을 암기.
- **수정 1**: 식별자 컬럼을 **명시적으로 drop**(Source/Dest IP·Port, Flow ID, Timestamp, Unnamed: 0) — *숫자여도 무조건 제거*.
- **수정 2**: drop을 **먼저** 한 뒤 수치형 선택 → inf→NaN→dropna.
- **수정 3**: 스케일러는 **train에만 `fit_transform`, test는 `transform`만** → 테스트 정보가 학습에 새지 않음.
- `train_test_split(random_state=42, stratify=y)`로 클래스 비율 유지 + 재현성.

**(2) 캡쳐할 파일/코드 위치**
- `modules/preprocessing.py`:
  - `ID_COLUMNS` + `_drop_identifier_columns()` (식별자 drop)
  - 처리 순서 주석("식별자 drop → 수치형 선택 → ...")
  - `scaler.fit_transform(X_train)` / `scaler.transform(X_test)` 2줄
- **Before/After 코드 대비**: 옛 `function1.py`의 `select_dtypes(np.number)` 한 줄 vs 새 `preprocessing.py`

**(3) 발표 대사**
- **누수 정의 → ** "데이터 누수란, 실전에선 쓸 수 없는 정답 단서가 학습에 흘러든 상태입니다."
- **원인 → ** "IP·포트가 숫자라서 `select_dtypes`가 못 걸렀고, 모델은 트래픽이 어떻게 생겼는지가 아니라 '이 IP가 공격자냐'를 외워버렸습니다."
- **해결 → ** "그래서 식별자를 명시적으로 지우고, 스케일러는 train에만 학습시켜 테스트 정보가 새지 않게 했습니다."
- **한 문장 요약 → ** "모델에게 '주소'가 아니라 '행동'만 보게 만든 겁니다."

## 슬라이드 5 — 모델 선택 이유 & 비교

**(1) 넣을 내용**
- 비교한 3개 모델과 *선택 이유*:
  - **LogisticRegression**: 빠르고 해석 쉬운 베이스라인. **로그 손실(log loss)을 최소화**하는 선형 분류기.
  - **DecisionTree**: 비선형은 잡지만 분산이 커 과적합 경향(비교 기준점).
  - **RandomForest(최종)**: 트리 앙상블(bagging)로 분산↓, 스케일 가정 없이 비선형·상호작용 포착, `feature_importances_`로 설명 가능.
- 비교표(train/test accuracy, precision/recall/f1) → `result/model_comparison.csv`.

**(2) 캡쳐할 파일/코드 위치**
- `modules/evaluate.py`의 `_build_candidates()`(세 모델 + 주석), `compare_models()`
- `modules/train.py` 상단 docstring("왜 RandomForest인가")
- 결과물: `result/model_comparison.csv`

**(3) 발표 대사**
- **학습의 원리 → ** "모든 모델 학습은 결국 '비용(손실)을 최소화'하는 과정입니다. 로지스틱 회귀는 로그 손실을 줄이며 경계를 찾습니다."
- **왜 비교 → ** "한 모델만 쓰면 '이게 최선인지' 알 수 없어서, 단순→복잡 순으로 세 모델을 같은 조건(seed 42)에서 비교했습니다."
- **왜 RandomForest → ** "트래픽 특성은 스케일이 제각각이고 비선형이라, 스케일 가정 없이 잘 작동하고 특성 중요도로 설명까지 되는 랜덤포레스트를 최종 선택했습니다."

### 발표 시 꼭 살릴 3가지 (요약)
1. **누수가 왜 문제인지** 코드 한 줄(`select_dtypes`)로 짚고, 식별자 drop으로 해결한 과정.
2. **이유 있는 선택**: 왜 이 모델, 왜 이 지표(f1·recall), 왜 train/test를 함께 보는지.
3. **100%는 누수의 증거, 95~99%가 진짜** — 그리고 seed 고정으로 재현 가능.
